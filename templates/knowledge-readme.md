# Knowledge Store

What agents and humans have learned about this workspace's code, tools, and
project: one fact per note, in `notes/`. It opens as an Obsidian vault, and
any editor works. See `.harness/policies/knowledge.md` for the rules.

- `notes/<slug>.md`: active notes. Agents and humans may edit them.
- `archive/<slug>.md`: retired notes, kept for history and not searched.
- `INDEX.md`: generated by Mahler from the notes (`mahler knowledge index`).
  Don't edit it; your changes would be overwritten.

When `knowledge.repo` is set in `.harness/config.json`, this folder is a git
clone of that repo, shared by everyone working in the workspace. Mahler
commits and pushes after each `learn`, `verify`, and `import`, and pulls when
it writes a brief. After editing notes by hand, run `mahler knowledge sync`.
`INDEX.md` is gitignored; each clone builds its own.

## Commands

- `mahler learn --title "<claim>" --description "<sentences>" --tags a,b [--repos r] [--paths glob,glob] [--body-file f]`
- `mahler knowledge search <terms>`, or `--changed` from a worktree to find
  notes about the files the branch changes
- `mahler knowledge verify <slug>`: the note still holds, as of today
- `mahler knowledge sync`: in repo mode, pull others' notes and publish yours
- `mahler knowledge import <ledger-note>`: turn a decisions ledger note into a
  knowledge note (the audit uses it)

## Note Frontmatter

```yaml
title: "The fact itself, as a claim"
description: "One or two sentences an agent can act on from the index alone."
tags: [area, tool]
repos: [repo-name]          # empty: the whole workspace
paths: ["src/cache/**"]     # files the note is about, relative to the repo
status: active              # or retired (then move it to archive/)
sources: [DEV-123]
created: 2026-11-02
updated: 2026-11-02
verified: 2026-11-02
```
